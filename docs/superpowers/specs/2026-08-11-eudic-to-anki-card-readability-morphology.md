# Eudic-to-Anki 卡片可读性与构词线索增强规格

日期：2026-08-11

状态：已实施

## Problem Statement

当前 `TRVS-Lab` 语境锚点卡已经实现单词点击发音、正面例句和展开式背面，但实际复习仍存在三类问题。

第一，Anki Desktop 上的正面单词明显小于预期，而移动端显示正常。严格模型预检已经返回 `action=none`，并确认 Front、Back、CSS 都与项目资产完全一致，因此问题不是旧模板或旧样式没有同步，而是正面使用原生 `button` 元素后，不同 Anki 运行环境对按钮字体样式的处理存在差异。当前 `font` 简写不足以稳定覆盖桌面端的原生按钮样式。

第二，正面例句整体继承居中对齐。短句看起来整齐，但较长例句换行后，每一行都居中，阅读起点不断变化，不利于快速扫读。学习需要的是「句子块位于卡片中央，句内文本左对齐」，而不是整段文字逐行居中。

第三，背面的 `词族构词` 内容过于简略。现有内容可能只显示 `ascend v. 上升；晋升` 这样的词族成员，缺少词形变化、构词意义、目标词中文义，以及联想词的词性和中文义。学习者能看到相关单词，却很难理解这些单词为什么相关，也无法像《Word Power Made Easy》或《Merriam-Webster's Vocabulary Builder》那样借助可靠的构词关系建立可迁移的词汇网络。与此同时，卡片额外显示「词族构词」模块标题，增加了视觉噪声。

## Solution

保持现有单卡 Context Anchor 模型、字段集合和信息顺序，完成一次兼容的模板、样式与教练内容合同更新。

正面继续使用可点击、可聚焦的单词按钮播放发音，但显式重置跨平台原生按钮外观，并用独立字体属性固定单词的字体、字号、字重和行高，使 Anki Desktop 与移动端都按设计尺寸显示。正面例句改为宽度随内容变化、整体居中的文本块；文本块内部左对齐，长句换行后保持稳定的阅读起点。

背面继续使用现有 `word_family` / `词族构词` 字段，不新增 Anki 字段。模板移除可见的「词族构词」标题，构词内容占据完整可用宽度。字段内容使用两个逻辑行内提示直接表达信息：第一行是「拆解」，第二行是「联想」。完整单词必须带词性和简短中文义；词根、前缀和后缀提供中文构词义，但不添加词性。每个联想词同样带词性和中文义。

标准呈现示例：

> 拆解：ascend「v. 上升；晋升」→ ascension「n. 上升；晋升」（-ion「名词后缀」，词干变体为 ascens-；scend/scand「攀登、上升」）
>
> 联想：ascent「n. 上升；攀登」、descend「v. 下降；下去」

构词线索仍是可选内容。只有拆解可靠、能帮助理解目标词，并且存在有迁移价值的联想词时才生成；不可靠的词源故事、牵强拆词和仅重复整词释义的内容直接省略。普通卡片的构词区域控制为两个逻辑行，联想词保留 1～3 个，保持快速扫读节奏。

## User Stories

1. 作为在 Anki Desktop 上复习的学习者，希望正面单词按设计字号显示，以便一眼识别目标词。
2. 作为同时使用桌面端和移动端的学习者，希望目标词在不同设备上的视觉大小基本一致，以便形成稳定的复习体验。
3. 作为需要点击单词播放发音的学习者，希望字号修复不改变现有点击发音行为，以便继续使用单一步骤核对发音。
4. 作为使用键盘或辅助功能操作卡片的学习者，希望正面单词继续保留按钮语义和焦点能力，以便不因视觉修复降低可操作性。
5. 作为快速浏览卡片的学习者，希望短例句所在的文本块仍位于卡片中央，以便正面保持平衡。
6. 作为阅读较长例句的学习者，希望句子换行后各行左对齐，以便眼睛沿稳定的左边界继续阅读。
7. 作为在窄屏设备上复习的学习者，希望例句文本块不超出卡片可用宽度，以便避免横向滚动或裁切。
8. 作为依靠词形关系记忆的学习者，希望构词线索解释已知词如何变成目标词，以便把新词连接到已有词汇。
9. 作为中文母语学习者，希望构词线索中的完整单词都带简短中文义，以便无需再次查词。
10. 作为需要区分词类的学习者，希望构词线索中的完整单词带 `n.`、`v.`、`adj.`、`adv.` 等词性符号，以便看清派生过程中的词性变化。
11. 作为学习派生词的学习者，希望目标词本身也带词性和中文义，以便从拆解直接回到当前学习目标。
12. 作为学习词根词缀的学习者，希望前缀、后缀和词根显示简短中文构词义，以便理解各部分对整词意义的贡献。
13. 作为不希望混淆语言层级的学习者，希望词根和词缀不标注名词、动词等词性，以便把构词单位与完整单词区分开。
14. 作为希望扩展词汇网络的学习者，希望每个联想词都带词性和中文义，以便快速判断它与目标词的关系。
15. 作为控制卡片信息量的学习者，希望每条构词线索只保留 1～3 个高价值联想词，以便避免背面变成完整词典条目。
16. 作为重视理解而非死记的学习者，希望必要时看到一句简短的字面意义桥接，例如「向四周看」如何引出「谨慎」，以便形成可解释的记忆线索。
17. 作为重视准确性的学习者，希望低置信度词源、不透明历史音变和牵强拆词不出现在卡片上，以便避免形成错误记忆。
18. 作为学习不可拆分词或固定短语的学习者，希望没有可靠构词收益时整个区域自动省略，以便不显示占位符或空模块。
19. 作为快速确认答案的学习者，希望背面不再显示独立的「词族构词」标题，以便减少一次无意义的视觉停顿。
20. 作为仍需要识别内容类型的学习者，希望构词内容保留行内「拆解：」和「联想：」提示，以便快速定位两类信息。
21. 作为阅读背面信息的学习者，希望构词内容使用完整宽度而不是为已删除的标题保留空白列，以便中文注解自然换行。
22. 作为依赖历史 Anki 数据的学习者，希望本次更新不新增或删除 note 字段，以便已有卡片和遇见记录保持兼容。
23. 作为继续导入新词的学习者，希望下一次导入自动识别模板和样式变化并安全更新模型，以便无需手工编辑 Anki 模板。
24. 作为使用严格模型合同的学习者，希望模型更新后重新读取并校验 Front、Back 和 CSS，以便卡片写入前确认模板完整一致。
25. 作为已有旧式构词内容的学习者，希望模型更新不会自动改写所有历史 note 字段，以便模板更新与内容重写保持可控。
26. 作为再次遇见旧词的学习者，希望该词正常更新时生成新版构词线索，以便历史卡片逐步获得更完整的中文辅助。
27. 作为维护 skill 的实施人员，希望生成规则包含明确的正例和反例，以便 agent 在不同批次中保持相近的信息密度。
28. 作为维护导入流程的实施人员，希望不改变分类、音频、遇见聚合和卡片重置逻辑，以便本次改动集中在可读性与学习内容质量。

## Implementation Decisions

- 保留单词的语义化按钮元素、现有 `playAudio` 行为和隐藏音频字段。样式层重置标准及 WebKit 原生按钮外观，清除浏览器默认内边距、边框和背景，并显式设置字体族、`34px` 字号、字重和行高。对容易被 Anki Desktop 原生样式覆盖的字体属性使用足够高的优先级，不依赖单个 `font` 简写。
- 单词在桌面端和移动端使用同一名义字号，不为平台分别维护两套视觉尺寸。只有真实设备冒烟测试证明统一规则仍无法覆盖时，才使用 Anki 提供的平台类添加最小差异规则。
- 正面例句保持现有字体尺寸和行高。例句容器采用内容宽度、受卡片宽度约束并水平居中；容器内部设置左对齐。短句视觉上仍居中，长句换行后沿同一左边界排列。
- 保留现有 `word_family` JSON 键和 `词族构词` Anki 字段。字段名称作为内部兼容标识继续存在，但卡片模板不再渲染同名标题。
- 构词区域从带标签的双列行改为占据完整内容宽度的独立文本块。空字段继续依靠模板条件完全隐藏，不保留空白间距。
- `word_family` 使用纯文本保存，不由 agent 写入 HTML。两个逻辑行以普通换行分隔，样式层保留换行显示。模板负责呈现，内容字段不承担标签样式或布局职责。
- 非空 `word_family` 采用固定结构：第一行以 `拆解：` 开头，第二行以 `联想：` 开头。两行直接呈现在背面，不增加外层模块标题。
- 「拆解」按「构词来源或组成部分 → 目标词」组织。已知基础词和目标词均使用 `word「词性 中文义」` 形式；词根、前缀和后缀使用 `构词单位「中文构词义」` 形式，不添加词性。
- 完整单词优先使用 `n.`、`v.`、`adj.`、`adv.`、`prep.`、`phr.`、`phr.v.` 等简写。只标注与当前构词关系有关的词性和义项，不罗列一个单词的全部词性。构词线索中的动词默认使用 `v.`；只有及物性本身对理解构词关系有明确帮助时才细分为 `vt.` 或 `vi.`。
- 「拆解」必须给出目标词的词性和简短中文义。存在可靠的词干变体、同形异体或透明词性派生时，可以在括号中补充一句简短说明；说明用于连接意义，不扩展为长篇词源史。
- 「联想」保留 1～3 个最有迁移价值的同根词、反向词缀词或常见派生词。每个联想词都使用 `word「词性 中文义」` 形式，不只列英文单词。
- 构词线索的选材优先级为：透明派生关系、生产力较高的常见词缀、能解释整词含义的可靠词根、常见且有助于迁移的同族词。整词翻译冒充拆解、低置信度词源故事、无法解释当前义项的历史关系和无帮助的相似拼写不生成。
- 无法同时提供可靠拆解和至少一个有价值联想词时，`word_family` 留空。不得写入 `-`、`无`、「不可拆分」或其他占位内容。
- 教练内容合同补充结构规则、中文注解规则、词性规则、长度边界和正反例。Coach 模块说明与面向使用者的 Anki 说明使用相同术语，避免「词族」「构词」「词根」在不同文档中指代不同内容。
- Validator 继续把 `word_family` 视为可选字段。非空时校验两个逻辑行、固定行内提示、禁止占位符和禁止 HTML；同时限制联想词数量，并检查箭头后的目标词与每个联想词包含词性和中文义。中文释义内部的 `、` 不计作联想词分隔符；带前导／后置连字符的词缀和使用 `/` 标出的词根不得带词性。没有形式标记的裸词既可能是基础词，也可能是 `spect` 一类词根，Validator 不猜测其角色；基础词标注和裸词根不标注由 agent 合同与人工抽查保证。词源是否正确、中文义是否恰当等语义质量同样不使用脆弱的正则表达式伪造校验。
- 既有 note type 名称、Context Anchor 模板数量、字段顺序和字段集合保持不变。Front、Back 和 CSS 资产变化会被严格模型合同识别为兼容 `update`；导入器按现有流程自动覆盖并二次验证。
- 模板更新只改变呈现，不批量重写 Anki 中已有的 `词族构词` 字段。新建 note 和因新遇见而更新的 note 使用新版生成合同；旧 note 可随以后再次遇见逐步更新。
- 本次改动不改变正面字段范围、背面其他字段顺序、来源例句决策、`learn` / `defer` / `skip` 路由、Edge-TTS 硬门、遇见统计、历史语境或进度重置语义。

## Testing Decisions

- 自动化测试只断言外部可观察合同：正面目标词是否仍可点击发音且具有稳定字号规则，例句是否表现为居中容器内左对齐，背面是否隐藏模块标题并完整显示字段内容，教练 JSON 是否接受或拒绝规定格式。测试不锁定辅助函数名称或内部拆分方式。
- 主要模板测试接缝沿用现有完整模型资产规格测试。一次读取模型引用的 Front、Back 和 CSS，验证三者作为一个可同步模型满足以下行为：正面字段范围不变、单词按钮拥有跨平台字体覆盖规则、例句容器采用目标对齐方式、背面不包含可见「词族构词」标签、空 `词族构词` 仍整块隐藏、其他背面字段顺序不变。
- 教练内容测试接缝沿用现有命令级 Validator 测试。通过完整 JSON 输入验证：空 `word_family` 可以通过；符合两行结构并含中文注解和词性符号的内容可以通过；占位符、HTML、缺少固定行内提示、超过 3 个联想词或额外逻辑行会给出可读错误。
- 字段映射测试沿用现有 Anki note 映射测试，确认带换行的 `word_family` 原样写入 `词族构词` 字段，不丢失中文引号、词性符号或换行，也不新增 Anki 字段。
- 模型合同回归沿用现有同步 Fake Client 测试，确认旧资产状态产生 `update`，自动覆盖后 Front、Back、CSS 严格一致；已有 note 字段和未知额外字段仍按既有安全规则保留。
- 增加正例夹具，至少覆盖 `ascension`、`irreversible`、`circumspect` 和 `benevolent`，验证基础词、目标词和联想词均带当前相关词性及中文义，词根词缀只有中文构词义。
- 增加反例夹具，覆盖仅列 `ascend v. 上升；晋升`、只列英文联想词、强行拆解不可透明分析的单词、把固定短语当作词根词缀拆解，以及在字段中嵌入 HTML 的情况。
- 自动化测试不判断某个历史词源结论是否学术正确。实施完成后人工抽查一批真实教练输出，确认拆解可靠、中文义简洁、词性与当前关系一致，普通构词区域能在约两行内扫完。
- 真实 Anki 冒烟测试不纳入默认自动化测试。实施完成后在 Anki Desktop 和至少一个移动端分别检查同一张卡：单词视觉大小、点击发音、短句居中效果、长句换行左边界、夜间模式、构词区域宽度、字段为空时的隐藏行为。
- 默认回归继续运行完整 `unittest` 测试集，确保分类、音频硬门、模型严格校验、导出限频保护和遇见聚合行为没有变化。

## Out of Scope

- 不新增、删除或重命名 Anki note 字段。
- 不新增卡片模板，不恢复召回卡、挖空卡或多方向卡片。
- 不批量重写已有 note 的 `词族构词` 内容。
- 不接入外部词源数据库、词典 API 或自动词源检索服务。
- 不追求完整词源史、拉丁语或希腊语音变课程，也不复制《Word Power Made Easy》或《Merriam-Webster's Vocabulary Builder》的受版权保护内容。
- 不要求每个单词或短语都有构词线索；没有可靠学习价值时继续留空。
- 不改变语境释义、IPA、英英释义、来源词块、历史语境、遇见次数和最近遇见日期的显示顺序。
- 不改变欧路导出、日期范围限频保护、分类路由、Edge-TTS、Anki 进度重置或云同步行为。
- 不为桌面端和移动端设计不同的卡片信息架构。
- 不在本规格中实施模板、CSS、Validator 或文档改动，也不修改本地 Anki 数据。
- 不把本规格发布到 issue tracker；本次交付只保存为项目内本地文档。

## Further Notes

- `action=none`、`front=exact`、`back=exact` 和 `css=exact` 已排除「Anki 使用旧模型」这一原因。实施时应把桌面端字号问题作为原生按钮样式差异处理，不再通过重复同步模板排查。
- 「构词线索」是本规格中的功能术语，用于同时覆盖透明词形派生、常见词根词缀和高价值词族联想。Anki 内部字段仍名为 `词族构词`，但该名称不再显示在卡片上。
- 推荐内容示例：

  - `irreversible`
    - 拆解：ir-「不」+ reverse「v. 逆转；颠倒」+ -ible「能够……的」→ irreversible「adj. 不可逆转的」
    - 联想：reversible「adj. 可逆的」、reversibility「n. 可逆性」
  - `circumspect`
    - 拆解：circum-「环绕、四周」+ spect「看」→ circumspect「adj. 谨慎的；考虑周全的」，字面是「向四周看」
    - 联想：inspect「v. 检查」、prospect「n. 前景」、retrospect「n. 回顾」
  - `benevolent`
    - 拆解：bene-「好、善」+ vol/volent「意愿、希望」→ benevolent「adj. 仁慈的；乐善好施的」
    - 联想：benevolence「n. 仁慈；善意」、malevolent「adj. 恶意的」

- 应省略的典型情况包括：固定短语、不可透明拆分的常用词、只有遥远历史关系而无法帮助当前理解的词，以及 agent 无法高置信度解释的构词关系。
