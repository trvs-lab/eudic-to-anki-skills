# Eudic-to-Anki 语境锚点卡重设计规格

日期：2026-08-10

状态：已确认，待实施

## Problem Statement

当前 `eudic-to-anki` skill 按标准 Anki 间隔重复思路设计，把词汇分成 `focus`、`passive`、`ignore`，并为部分词同时生成短语块锚点卡和召回卡。这种设计与实际使用方式不匹配：复习时不会根据记忆强度选择 Anki 评分，而是快速浏览每张卡并统一点击「认识」。因此，额外的召回卡、短语块学习句、挖空任务和分类标记增加了制卡与复习负担，却没有形成相应的学习收益。

现有卡片也没有把欧路词典保存的真实阅读语境放在最重要的位置。正面以人工生成的短语块和学习句为主，来源例句退到背面；背面信息层级较多，分类符号和生成内容占据注意力。学习者很难在几秒内完成「看到原词和原句、判断当前义项、确认答案」这一最关键的过程，复习时间随生词增长而迅速膨胀，最终难以坚持。与此同时，欧路记录并不保证每个词都有完整、长度合适的来源句；如果流程只接受原句，会产生无例句卡片或丢弃本来有效的词条。

实际需要的不是一套标准 Anki SRS 课程，而是一条轻量的阅读后巩固流程：每天从欧路词典取得生词和来源例句，用一张语境锚点卡快速确认当前义项；同一词再次在阅读中出现时，更新卡片、积累历史语境并重置进度，让真实阅读中的再次遇见决定复习机会。

## Solution

把 `eudic-to-anki` 重设计为「真实阅读语境驱动的词汇巩固工具」。每个有效单词或短语只生成一张 `TRVS-Lab` 语境锚点卡，不再生成召回卡。

卡片正面只显示单词和一条适合学习的「卡片例句」。有自然、长度合适的来源句时优先保留；来源句过长或干扰信息过多时适量删减或改写；没有来源句时由 agent 围绕核心常用义生成实用例句。单词可点击或轻触发音，不显示释义、分类、例句来源类型、提示语或额外操作控件。正面交互参考 `9c5257f` 之前的设计，保留单词点击发音和卡片例句中目标词形高亮，但不恢复旧版背面的冗余内容。

卡片背面保留正面，并按学习价值从上到下直接展示：当前语境中的中文释义、美式 IPA、简短英英释义、来源词块及其中文义、真正有帮助的词族或构词提示、最近 2～3 条历史语境，以及遇见次数和最近遇见日期。所有信息默认展开，不使用折叠；缺少或没有学习价值的可选字段直接隐藏。分类标记不出现在卡片上。

有效词条分为 `learn`、`defer`、`skip` 三组，分别导入 `words::learn`、`words::defer`、`words::skip`。无效碎片使用内部状态 `reject`，不进入 Anki。再次导入 `defer` 中的同一词条时，卡片自动移入 `learn`；`learn` 保持在 `learn`；`skip` 保持在 `skip`，等待人工移动或删除。只要检测到新的真实遇见记录，现有卡片就更新语境和统计，并重置为新卡。

这套流程不要求改变现有复习习惯。翻到背面后可以继续统一点击「认识」。学习强度由真实阅读中的再次查词次数调节，而不是由 Anki 评分按钮调节。普通卡片的目标浏览时间为 3～5 秒，只有需要进一步确认的词才继续阅读背面的次要信息。

## User Stories

1. 作为每天阅读英文原版书的学习者，希望直接下载欧路词典生词本，以便省去手工复制单词的步骤。
2. 作为依赖真实阅读语境记忆单词的学习者，希望保留欧路词典记录的来源例句，以便回到第一次遇见该词时的理解线索。
3. 作为快速浏览卡片的学习者，希望每个词只生成一张卡片，以便控制每日复习数量。
4. 作为不使用主动召回训练的学习者，希望停止生成召回卡和挖空卡，以便避免不符合实际习惯的额外任务。
5. 作为重视阅读理解的学习者，希望正面首先看到单词和当前卡片例句，以便先根据语境做一次短暂判断。
6. 作为需要确认发音的学习者，希望点击或轻触正面的单词即可播放发音，以便不增加可见按钮和操作步骤。
7. 作为在不同设备复习的学习者，希望点击发音在 Anki 桌面端和移动端都能使用，以便保持一致的卡片体验。
8. 作为阅读变形词和不规则词形的学习者，希望卡片例句中的目标词形得到高亮，以便快速定位该词在句子中的位置。
9. 作为快速确认词义的学习者，希望背面最先显示当前语境对应的简短中文释义，以便在翻卡后立即得到答案。
10. 作为需要稳定语音表征的学习者，希望美式 IPA 直接显示在背面，以便在需要时快速核对读音。
11. 作为希望建立词义边界的学习者，希望背面直接显示简短英英释义，以便理解中文标签未覆盖的语义范围。
12. 作为希望迁移到其他文本的学习者，希望看到来源例句中的自然词块及其中文义，以便记住真实搭配，而不是人工制造的练习句。
13. 作为希望利用词形关系记忆的学习者，希望看到真正有帮助的词族关系，以便把新词连接到已经认识的词。
14. 作为希望利用构词规律记忆的学习者，希望只在构词分析准确且有帮助时显示提示，以便避免牵强词根造成误导。
15. 作为快速复习的学习者，希望所有有用信息直接展开，以便减少点击折叠区的操作。
16. 作为快速复习的学习者，希望可选字段为空时整段隐藏，以便避免空占位符和无意义视觉噪声。
17. 作为通过多次真实遇见形成记忆的学习者，希望背面显示最近的历史语境，以便比较同一词在不同文本中的使用方式。
18. 作为需要判断熟悉度的学习者，希望看到累计遇见次数，以便知道该词已经在阅读中出现过多少次。
19. 作为需要判断记忆新鲜度的学习者，希望看到最近遇见日期，以便知道当前语境是否仍然接近最近阅读。
20. 作为不希望被系统评级影响的学习者，希望卡片不显示 `learn`、`defer`、`skip` 或优先级符号，以便把注意力放在词义和语境上。
21. 作为统一点击「认识」的学习者，希望现有 Anki 操作方式继续可用，以便不增加新的评分规则。
22. 作为依赖再次导入触发复习的学习者，希望同一词出现新的真实遇见记录时重置卡片进度，以便再次在新卡队列中遇见该词。
23. 作为重复执行导入命令的学习者，希望完全相同的遇见记录不会重复增加次数或历史语境，以便统计保持准确。
24. 作为持续阅读的学习者，希望 `learn` 中的词再次导入后仍留在 `learn`，以便持续巩固重要词汇。
25. 作为控制当前学习量的学习者，希望暂缓词先进入 `defer`，以便保留词条但不混入主要学习组。
26. 作为相信重复查词具有学习价值的学习者，希望 `defer` 中的词再次查到后自动移入 `learn`，以便把真实重复遇见转化为学习信号。
27. 作为希望保留人工决定权的学习者，希望完整但低价值的单词、短语、专名或虚构词进入 `skip`，以便在 Anki 中决定是否删除。
28. 作为希望避免误删候选词的学习者，希望 `skip` 卡片也保留单词、卡片例句和解释信息，以便做出删除或保留判断。
29. 作为希望控制 `skip` 状态的学习者，希望重复导入不会仅因次数增加就自动把 `skip` 移入 `learn`，以便保持人工决定权。
30. 作为清理低价值词条的学习者，希望可以直接在 Anki 中删除 `skip` 卡片，以便不维护额外排除列表。
31. 作为以后可能再次遇到已删除词条的学习者，希望新的欧路遇见记录仍可重新创建卡片，以便删除不会永久屏蔽一个词。
32. 作为希望保持数据整洁的学习者，希望乱码、HTML 残片、标点碎片和无法独立成立的文本被判定为 `reject`，以便这些内容不进入 Anki。
33. 作为担心重复卡片的学习者，希望大小写、首尾空白和重复空格不会造成同一词条的多个 note，以便每个词只维护一份历史。
34. 作为同一天可能多次遇见同一词的学习者，希望导入时合并这些真实遇见记录，以便保留不同语境而不生成重复卡片。
35. 作为使用欧路词典时间筛选的学习者，希望遇见时间按本地时区保存，以便卡片日期与实际阅读日期一致。
36. 作为需要可靠制卡结果的学习者，希望缺少卡片例句、释义、IPA 或音频等关键数据时在导入前得到明确校验结果，以便避免生成不可用卡片。
37. 作为希望快速完成每日流程的学习者，希望预演能汇总 `learn`、`defer`、`skip`、`reject`、新增、更新和迁移数量，以便在真实导入前判断结果是否合理。
38. 作为依赖 Anki 同步的学习者，希望导入完成后沿用现有同步行为，以便桌面端和移动端获得相同卡片。
39. 作为查到没有来源例句的有效词条的学习者，希望 agent 生成一条实用、自然的卡片例句，以便仍能通过语境理解和记忆该词。
40. 作为遇到过长来源句的学习者，希望 agent 在不改变当前义项的前提下适量删减或改写，以便正面例句可以快速阅读。
41. 作为重视真实阅读记录的学习者，希望改写前的原始来源句仍被内部保存，以便生成内容不会覆盖原始数据。
42. 作为希望保持卡面简洁的学习者，希望例句的 `source`、`adapted` 或 `generated` 类型只在内部记录，以便正面不增加来源标签。
43. 作为查看历史语境的学习者，希望纯生成例句不被当成真实历史语境，以便历史区域只反映实际阅读记录。
44. 作为再次查到无来源例句词条的学习者，希望这次查词仍然更新遇见次数、日期和学习状态，以便来源缺失不会丢失重复遇见信号。
45. 作为学习无来源多义词的学习者，希望 agent 优先选择最高频、迁移价值最高的核心义，以便避免根据缺失语境猜测冷门义项。
46. 作为重视发音质量的学习者，希望新音频统一由 Microsoft Edge 在线 TTS 的神经网络声线生成，以便避免不同 TTS 服务造成明显音质差异。
47. 作为遇到临时音频服务故障的学习者，希望相同生成请求自动重试一次，以便短暂网络波动不会立即中断整个流程。
48. 作为不接受低质量系统发音的学习者，希望第二次生成仍失败时停止导入并报告错误，以便系统不会静默回退到操作系统 TTS。
49. 作为需要可预测导入结果的学习者，希望音频失败时不新增、更新、重置或移动任何 Anki 卡片，以便一次失败不会留下半完成状态。

## Implementation Decisions

- 产品定位从「短语块主动召回系统」改为「真实阅读语境驱动的快速词义确认系统」。真实来源例句是首选记忆锚点；来源缺失或不适合直接制卡时，人工生成内容负责提供简短、实用的替代语境。
- `TRVS-Lab` 改为单模板 note type。每个有效 note 只生成一张「Context Anchor」卡；删除「Chunk Recall」模板及其条件生成逻辑，不再要求挖空字段。
- 正面只允许出现 `单词` 和 `卡片例句`。`卡片例句` 对所有进入 Anki 的有效词条必填；单词点击区域触发 `发音` 字段中的音频，页面不显示独立音频按钮。
- agent 按三个分支生成 `卡片例句`：自然且长度合适的来源句只做 HTML、空白和明显噪声清理，例句来源记为 `source`；过长、截断或含大量无关背景的来源句进行最小必要删减或改写，例句来源记为 `adapted`；没有可用来源句时围绕核心常用义生成实用例句，例句来源记为 `generated`。
- `卡片例句` 必须是完整、自然、可独立理解的句子，并包含目标单词或其正确变形。默认长度为 8～16 个英文词，确有必要时可以稍长；避免额外引入低频词、专名和复杂背景。
- 改写来源句时必须保留目标词在原文中的义项、基本情境、事实关系和语气，不得为了缩短而改变说话人、因果关系或褒贬含义。允许删除旁支从句、重复修饰和理解目标词不需要的专名背景。
- 没有来源句时，生成例句优先使用最高频、迁移价值最高的核心义。多义且缺少足够信息时最多保留 1～2 个核心常用义，不猜测冷门义项；分类不确定时默认进入 `defer`。
- 正面沿用旧版基于文本节点的目标词形高亮策略，支持常见屈折变化和不规则形式；不得通过重写整段 HTML 的方式高亮，以免破坏例句标记。
- 背面使用 `FrontSide` 保留正面内容，然后依次显示：`语境释义`、`音标`、`英英`、`来源词块`、`词块释义`、`词族构词`、`历史语境`、`遇见次数` 和 `最近遇见`。
- 背面不使用折叠控件。视觉上分为「核心答案」「迁移提示」「历史信息」三层，但不要求学习者每次读完所有层级。
- `语境释义` 必须与当前 `卡片例句` 表达的义项一致，保留词性并使用简短、自然的中文词典标签。纯生成例句的释义必须对应所选核心常用义。
- `英英` 必须针对当前义项，通常为 6～18 个英文词的一句简明解释；不得使用百科式长定义或只列同义词。
- `来源词块` 最多保留一个，只用于 `source` 或 `adapted` 例句，必须能在当前 `卡片例句` 中逐字找到，并具有独立学习价值；`adapted` 例句中的词块还必须能追溯到对应原始来源。纯生成例句不伪装成来源词块；无法提取自然词块时留空。
- `词族构词` 合并旧有词根和词族职责。优先展示常见派生关系或透明、可靠的词缀关系；整词翻译、低置信度词源故事和无帮助拆分留空，不再使用 `-` 或 `无` 占位。
- 通用 `常用搭配` 不再是必填卡片字段。需要保留的搭配信息由 `来源词块` 承担，以减少生成成本和背面长度。
- `历史语境` 只显示当前语境之前最近 2～3 条真实来源记录，按时间从近到远排列。`source` 记录显示清理后的句子，`adapted` 记录显示适合卡片阅读的精简版本；对应原始来源仍保存在内部遇见记录中。`generated` 例句不进入历史语境，避免把模型生成内容伪装成阅读记录。
- `遇见次数` 按不同的真实遇见记录累计，不按导入命令执行次数累计。`最近遇见` 使用欧路导出的本地时间；显示层只展示本地日期。
- Export 模块继续保存欧路 API 返回的 `context_line`，并把 `add_time_utc`、`add_time_local`、分类来源和稳定遇见标识传递到后续步骤，不得在中间 JSON 合并时丢失。
- 稳定遇见标识由欧路类别、规范词条、欧路时间和规范化原始来源共同形成。没有来源句时原始来源部分允许为空，但时间仍参与标识。相同标识重复导入时不增加遇见次数、不重复追加历史，也不把同一次遇见误判为新的学习信号。
- 同一批次出现同一规范词条的多条记录时，按时间聚合为一个 note 更新：最新一条记录生成当前 `卡片例句`；其余带真实来源的不同语境进入历史记录，纯生成例句不进入历史。
- note 增加稳定的 `规范词形`。匹配时对 Unicode、大小写、首尾空白和连续空格做规范化，但保留短语内部有效标点；`单词` 字段继续保存适合展示的原始形式。
- note 的内容字段调整为：单词、规范词形、音标、语境释义、英英、原始来源、卡片例句、例句来源、来源词块、词块释义、词族构词、历史语境、遇见次数、最近遇见、遇见记录、学习分组、发音。
- `原始来源`、`例句来源`、`遇见记录` 和 `学习分组` 是内部字段，不在卡片模板中显示。`例句来源` 只能是 `source`、`adapted` 或 `generated`。`学习标记`、`目标短语块`、`短语块锚点`、`短语块例句`、`短语块挖空` 和旧 `常用搭配` 从新版模型中移除。
- 分类词汇改为 `learn`、`defer`、`skip`、`reject`。旧 `focus`、`passive`、`ignore` 不再进入新 JSON 合同、Anki 字段或标签。
- `learn` 用于值得在阅读、听力、口语或写作中稳定掌握的词，包括高频、多义、搭配丰富、容易误解或对长期阅读主题重要的词。
- `defer` 用于完整、有识别价值但当前学习收益较低的词。首次出现时保留；再次出现新的真实遇见记录时自动升级为 `learn`。
- `skip` 用于完整但明显低收益的词或短语，例如一次性专名、虚构词、极冷门术语和当前长期目标以外的内容。`skip` 仍生成完整语境锚点卡，不自动挂起，也不因重复次数自动升级。
- `reject` 只用于无法构成有效词条的输入，例如乱码、HTML 残片、标点碎片、异常单字母和无法独立成立的截断文本。`reject` 只出现在预演报告中，不生成 note 或卡片。
- Anki 牌组固定为 `words::learn`、`words::defer`、`words::skip`。牌组是人工操作时可见的当前状态；内部 `学习分组` 字段和 `group::learn`、`group::defer`、`group::skip` 标签用于导入校验与检索，不在卡面显示。
- 自动状态迁移为：新词按分类进入对应牌组；现有 `learn` 保持 `learn`；现有 `defer` 遇到新的真实记录后进入 `learn`；现有 `skip` 保持 `skip`。人工把卡片移动到其他受管牌组后，下一次导入以该牌组为当前状态，再应用迁移规则。
- 现有 note 在出现新的真实遇见记录时更新卡片例句、例句来源、当前义项、历史、次数、日期、解释字段和音频，并通过 AnkiConnect 重置为新卡。无来源记录同样计为一次真实遇见并参与 `defer → learn`；它会生成新的卡片例句，但不会向历史语境追加生成内容。完全相同的遇见记录重复导入时保持幂等，不重置进度。
- 用户删除 note 后不保存永久排除记录。将来出现新的欧路记录时，导入器可以重新创建同一词条。
- 分类信息只存在于牌组、标签和内部字段。模板不得渲染分类文字、`★`、`◇`、`×` 或任何等价视觉标记。
- Audio 模块生成新音频时固定使用 Microsoft Edge 在线 TTS，通过 Python `edge-tts` 调用神经网络声线。默认声线保持 `en-US-GuyNeural`，允许通过现有显式配置更换声线，但不得在失败时自动切换声线或服务。
- 已存在且可验证的 Anki `[sound:...]` 音频或由使用者显式选择的本地音频文件可以直接复用。这属于保留已有音频，不属于服务失败后的自动回退。
- 真实导入前必须使用与正式生成相同的服务和声线完成一次在线音频探测。网络错误、超时、WebSocket 错误、服务异常、未收到音频、输出文件缺失、空文件或无效 MP3 均视为音频生成失败。
- 音频生成失败后，使用完全相同的服务、声线、文本和参数短暂等待并重试一次。总尝试次数固定为 2 次，不得继续无限重试。
- 第二次尝试仍失败时必须终止本次导入，报告服务名称、失败单词、声线、尝试次数和可读错误原因，并说明未执行 Anki note 导入。不得调用 macOS `say`、操作系统 TTS、浏览器语音合成、其他在线 TTS、备用声线或任何降质音频方案。
- 音频探测和全部待生成音频必须在 Anki note 新增、更新、进度重置、牌组移动和同步之前完成。任意一个词在重试后仍失败时，不得对 Anki note 或 card 执行部分写入；本地临时音频和探测文件应被清理。
- 缺少 `edge-tts` 依赖、命令配置无效或声线名称无效属于确定性配置错误，可以直接终止并给出修复说明，不需要进行无意义重试，但同样禁止任何回退。
- 最终导入仍要求每个有效 note 的 `发音` 字段包含有效的 Anki `[sound:...]` 标签。skill 内所有关于系统 TTS 回退的说明、执行授权和示例必须移除，agent 不得自行扩大音频提供方范围。
- Validator 按新 JSON 合同校验词条有效性、卡片例句、美式 IPA、当前义项释义、英英释义、可选词块一致性、词族构词质量、分类值、遇见记录和音频准备状态。`原始来源` 允许为空，但 `卡片例句` 必须非空并包含目标词或正确变形；`source`、`adapted`、`generated` 必须与原始来源是否存在及处理方式一致。删除所有召回卡和必填短语块规则。
- Import 模块继续通过 AnkiConnect 查找 note、读取 note/card 信息、更新字段和标签、移动卡片、重置进度并同步。模型升级后只允许每个有效 note 存在一张受管卡片，发现遗留召回卡或重复 note 时必须在预演中明确报告。
- 本次改动是 `TRVS-Lab` 的第二次破坏性模型升级。实施前必须备份并同步 Anki。升级工具需要删除旧召回模板产生的卡片并切换到单模板模型；不得静默保留旧 recall 卡。无法安全完成原位迁移时，应停止并给出清空旧 `TRVS-Lab` note 后重新导入的明确步骤。
- 预演报告至少包含：输入记录数、聚合词条数、`learn`、`defer`、`skip`、`reject` 数量、新增数、更新数、`defer → learn` 数、幂等跳过数、待重置卡片数和遗留模型问题。

## Testing Decisions

- 测试只断言外部可观察行为：生成了几张卡、卡片位于哪个牌组、note 对外字段是什么、历史和次数如何变化、是否调用进度重置、模板最终显示或隐藏什么。不得通过私有辅助函数的具体实现方式锁死代码结构。
- 主要测试接缝使用现有 AnkiConnect 客户端替身，从一次完整导入操作进入，覆盖「读取现有 note → 聚合新遇见 → 更新字段和标签 → 状态迁移 → 移动单卡 → 重置进度」的完整行为。这是本功能的最高层主要接缝，优先在此覆盖状态转换和幂等行为。
- 沿用现有卡片路由测试的 Fake Client 方式，扩展为单模板和三牌组行为；不再围绕模板序号分别测试 Anchor 与 Recall。
- 沿用现有模型规格测试，验证新版模型只包含一个卡片模板、字段集合符合新合同、正面只引用单词／卡片例句／发音、背面不包含分类标记、例句来源标记和折叠控件。
- 沿用现有模型同步测试，验证旧双模板模型被识别为需要升级，升级后不存在召回模板和分类标记样式；迁移无法安全执行时返回可操作错误，不静默继续。
- 沿用现有字段映射测试，验证当前义项释义、来源词块、词族构词、历史、次数、日期、内部分组和音频能够完整写入 Anki note。
- 沿用现有 Validator 命令级测试，验证 `learn`、`defer`、`skip` 的有效输入能够通过，`reject` 输入不会进入导入 payload，缺少关键字段或低质量构词提示会给出明确错误。
- 增加状态转换验收：新 `learn` 进入 `words::learn`；新 `defer` 进入 `words::defer`；新 `skip` 进入 `words::skip`；新 `reject` 不调用新增 note。
- 增加重复遇见验收：`defer` 收到新的遇见记录后移入 `learn` 并重置；`learn` 收到新的遇见后留在原组并重置；`skip` 收到新的遇见后留在原组并重置。
- 增加幂等验收：同一遇见标识重复执行不增加次数、不重复历史、不迁移牌组、不重置进度；同一词但不同时间或不同来源句被识别为新的遇见。
- 增加批内聚合验收：同一词的多条新记录只更新或创建一个 note，最新语境显示在正面，较早语境进入历史，次数按不同记录增加。
- 增加例句生成验收：没有原始来源时生成 8～16 个词左右的完整实用例句，包含目标词或正确变形，例句来源为 `generated`，并且不会进入历史语境。
- 增加例句改写验收：过长或噪声较多的来源句生成更短的 `adapted` 例句，保留目标义项和事实关系，原始来源不被覆盖并随遇见记录保存。
- 增加原句保留验收：自然、长度合适的来源句只做必要清理，例句来源为 `source`，不得产生无意义改写。
- 增加无来源重复遇见验收：无来源记录仍增加次数、更新日期、重置进度并触发 `defer → learn`，但不向历史语境写入生成句。
- 增加音频瞬时失败验收：第一次 Edge-TTS 请求失败、第二次相同请求成功时继续导入，并确认两次请求使用完全相同的服务、声线、文本和参数。
- 增加音频终止验收：同一请求连续两次失败时停止导入，错误信息包含服务、单词、声线和尝试次数；AnkiConnect 不得收到 note 新增、字段更新、进度重置、牌组移动或同步调用。
- 增加音频输出校验：未生成文件、零字节文件或无效 MP3 按失败处理并只重试一次，不能仅凭命令退出码为 0 判定成功。
- 增加无回退验收：Edge-TTS 失败后不得调用 macOS `say`、系统 TTS、浏览器语音合成、其他在线服务或备用声线。
- 增加已有音频验收：note 已有有效 Anki 音频或导入明确指定本地音频时直接复用，不调用 Edge-TTS，也不把该行为记为回退。
- 增加音频预检验收：正式处理前使用当前声线完成在线探测；探测连续失败后不得开始生成其他音频或修改 Anki 数据，探测临时文件在成功或失败后均被清理。
- 增加人工操作验收：人工移动到另一个受管牌组后，导入器读取实际牌组作为当前状态；人工删除后，新的遇见记录可以重新创建 note。
- 增加模板行为验收：正面没有释义、分类和例句来源标签；点击单词能够触发音频；卡片例句高亮不会破坏原 HTML；背面字段按确认顺序出现；空可选字段整段隐藏；历史最多显示 3 条；底部只显示次数和日期。
- 增加牌组搜索验收：导入器能在 `words` 基础牌组、三个新牌组和遗留短语块牌组中发现同一 note，避免升级期间生成重复卡片。
- 增加真实 AnkiConnect 冒烟测试说明，但不纳入默认自动化测试：在已备份的测试 Anki 配置中完成模型升级、导入、再次导入、牌组迁移、进度重置、点击发音和同步抽查。
- 默认回归命令继续运行完整 `unittest` 测试集。旧短语块／召回卡测试应被替换或重写，不能仅删除覆盖而不补充新行为测试。

## Out of Scope

- 不设计基于「重来」「困难」「认识」「简单」评分的自适应 Anki SRS 规则。
- 不生成召回卡、挖空卡、拼写卡、中译英卡或多方向卡片。
- 不生成独立短语块音频、来源例句音频或多口音音频。
- 不实现音频提供方自动切换、备用声线、离线系统 TTS 或低质量发音回退。
- 不把纯生成例句标记为真实来源，也不把它写入历史语境；原始来源和卡片例句必须分开保存。
- 不建立 Anki 之外的 defer 数据库、历史数据库或永久删除名单。
- 不自动删除或挂起 `skip` 卡片，也不根据遇见次数自动把 `skip` 升级为 `learn`。
- 不实现阅读器、欧路词典客户端或新的 Anki 复习界面。
- 不迁移旧召回卡的学习进度到新语境锚点卡。
- 不追求完整词典条目、全部词义、百科知识或详尽词源学解释。
- 不在本规格中实施代码改动、修改本地 Anki 数据或执行真实导入。
- 不把本规格发布到 issue tracker；本次交付只保存为项目内本地文档。

## Further Notes

- `learning-coach` 中最值得保留的原则是「先做极短尝试，再立即得到反馈」。在本方案中，这表现为正面停留约 1 秒，根据卡片例句猜测当前义项，然后翻到背面确认；不需要为此新增召回卡。
- `9c5257f` 之前的模板只作为正面交互参考，主要复用单词点击发音、例句展示和词形高亮。背面信息架构、字段合同和分类体系按本规格重新设计。
- 所有背面字段虽然直接展开，但不具有相同视觉权重。核心答案应能在一次扫视中完成；词块、词族和历史使用较弱层级，避免延长普通卡片的停留时间。
- 分类的价值只在于控制牌组和再次导入行为，不承担对学习者展示「这个词是否值得学」的职责，因此卡面完全移除分类标记。
- 欧路 API 能提供的时间和来源粒度决定历史统计的上限。若 API 只返回最近一次来源，需要在导出时保留每次取得的稳定快照，不能依靠下一次调用恢复已经被覆盖的旧语境。
- 当前音频实现使用 `edge-tts` 的 `Communicate.save` 访问 Microsoft Edge 在线语音服务，默认声线为 `en-US-GuyNeural`。现有导入器只有单次命令调用，尚未实现重试；仓库规则中仍存在 macOS `say` 回退说明，实施时必须删除。
- 实施顺序建议为：先改数据合同和分类器，再改遇见聚合与状态迁移，然后替换模型和模板，最后更新 Validator、文档和完整回归测试。所有部分应作为一次破坏性升级共同发布，避免新旧合同混用。
