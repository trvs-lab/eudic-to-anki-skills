# Eudic-to-Anki Anki 模型严格校验与安全同步规格

日期：2026-08-11

状态：已实施并校验

## Problem Statement

当前 `eudic-to-anki` 会在导入前检查 `TRVS-Lab` note type，并能识别旧双模板、错误模板名和部分遗留字段。note type 不存在时，真实导入可以自动创建；现有单卡模型缺少字段、模板或样式时，导入器也会尝试补充或更新。

这套检查只能证明模型大致兼容，不能证明 Anki 中的 Front、Back 和 CSS 与当前 Skill 内置版本严格一致。模板判断依赖关键字段、`playAudio` 和 CSS 版本注释等特征字符串。只要旧模板仍包含这些特征，即使 HTML、JavaScript 或 CSS 已经过期，也可能被误判为最新。CSS 文件发生变化但继续保留旧版本注释时，同样无法触发更新。

模型同步还发生在 Edge-TTS 音频准备之后。模板最终无法更新或验证时，导入虽然会停止，但可能已经发出无效的语音请求。更新完成后也没有重新读取 Anki 中的模型并验证实际结果，无法排除 AnkiConnect 调用成功但模型仍未达到目标状态的情况。

导入器与独立模型同步命令各自维护一套创建、字段补充、模板更新和 CSS 更新逻辑。两个入口对「最新模型」的判断可能逐渐产生差异。独立命令还允许只更新模板或只更新 CSS，可能主动留下部分更新状态。两个入口之间也没有共享的本机互斥保护，并发运行时可能同时检查和修改同一个 note type。

学习者需要的保证不是「模板看起来可用」，而是：每次真实导入开始生成音频或写入卡片之前，`TRVS-Lab` 必须已经创建或安全更新，并经过严格的内容验证；不兼容旧模型必须停止，不能以自动迁移为代价冒险破坏卡片与复习进度。

## Solution

建立统一的 `TRVS-Lab` 模型合同，由导入器和独立模型同步命令共同使用。模型合同加载本次运行采用的完整 model spec，对 Front、Back 和 CSS 做有限规范化后计算 SHA-256，并读取 Anki 中的模型进行同样处理。除 CRLF／LF 与文件末尾换行外，任何空格、HTML、JavaScript 或 CSS 差异都视为内容不一致。

模型预检把 Anki 状态分为五类：模型不存在、严格一致、结构兼容但内容不同、不兼容旧模型、存在未知额外字段。模型不存在时，dry-run 只报告将创建，真实导入自动创建；结构兼容但内容不同则安全补充缺失字段、更新 Front／Back、更新 CSS，再重新读取并严格验证；旧双模板、错误模板名或已知遗留字段继续硬停止；未知额外字段保留并警告，不自动删除。

真实导入必须在 Edge-TTS、deck 创建、媒体上传和 note 写入之前完成模型创建或更新以及二次验证。只有二次验证达到严格一致，后续卡片流程才能开始。更新中途失败不自动回滚；本次卡片导入立即停止，下次运行重新检查并继续修复。模型同步已经成功但后续音频或卡片导入失败时，安全模型变更保留，不随卡片失败回滚。

独立模型同步命令与导入器共享同一模型合同和本机非阻塞锁。独立命令提供只读 `--check` 和默认完整同步，不再允许仅更新模板或仅更新 CSS。真实导入不允许通过 `--no-ensure-model` 绕过模型创建与严格校验。模型更新作为完整导入的一部分时，仍只在卡片导入全部成功后触发 Anki sync；独立模型同步默认不触发云同步，只有显式传入 `--sync` 才执行。

## User Stories

1. 作为使用 Context Anchor 卡片的学习者，希望每次导入前都确认 Anki 模板与当前 Skill 严格一致，以便卡片显示和交互不受旧模板影响。
2. 作为依赖点击单词发音的学习者，希望 Front 中的 JavaScript 也参与严格比较，以便旧的音频交互代码不会被误判为最新。
3. 作为关注卡片背面信息顺序的学习者，希望 Back 的完整 HTML 参与严格比较，以便字段虽然齐全但布局过期时仍会更新。
4. 作为依赖统一视觉效果的学习者，希望 CSS 的完整内容参与严格比较，以便样式文件变化后能够同步到 Anki。
5. 作为跨平台使用仓库的学习者，希望 CRLF 与 LF 不造成无意义的重复更新，以便 Windows 与 macOS 的换行差异不影响判断。
6. 作为维护模板文件的开发者，希望文件末尾换行差异不造成无意义更新，以便编辑器保存习惯不影响模型指纹。
7. 作为维护模板文件的开发者，希望其他空格、HTML、JavaScript 和 CSS 变化都被识别，以便内容修改不会被宽松比较忽略。
8. 作为首次运行 Skill 的学习者，希望 `TRVS-Lab` 不存在时自动创建，以便不需要额外执行模板安装步骤。
9. 作为先执行 dry-run 的学习者，希望模型不存在时只看到创建计划而不修改 Anki，以便预演保持只读。
10. 作为使用兼容单卡模型的学习者，希望模板内容过期时自动覆盖为当前版本，以便不需要手工运行同步命令。
11. 作为使用兼容单卡模型的学习者，希望缺失的必需字段在模板更新前自动补充，以便新模板不会引用不存在的字段。
12. 作为在 note type 中保存额外数据的学习者，希望未知额外字段得到保留并显示警告，以便自动同步不会删除用户数据。
13. 作为从旧双卡模型升级的学习者，希望检测到 `Chunk Anchor`／`Chunk Recall` 时硬停止，以便复习进度不会因自动删除模板而损坏。
14. 作为使用错误模板名旧模型的学习者，希望导入器拒绝原地改名或删卡，以便避免破坏已生成卡片的调度数据。
15. 作为使用遗留字段模型的学习者，希望已知旧字段触发迁移阻断，以便结构不兼容不会被当作普通模板更新。
16. 作为遇到迁移阻断的学习者，希望错误信息列出具体问题，以便理解为什么不能自动更新。
17. 作为遇到迁移阻断的学习者，希望错误信息报告现有 `TRVS-Lab` note 数量，以便判断备份和重导范围。
18. 作为遇到迁移阻断的学习者，希望错误信息给出「备份、删除旧 notes、删除 note type、重新导入」步骤，以便能够完成安全升级。
19. 作为重视数据安全的学习者，希望工具绝不自动删除旧 notes、模板、字段或 note type，以便所有破坏性迁移都保留人工决定。
20. 作为运行真实导入的学习者，希望模型检查和安全更新发生在 Edge-TTS 之前，以便模板失败不会浪费语音请求。
21. 作为运行真实导入的学习者，希望模型二次验证发生在 deck、媒体和 note 写入之前，以便卡片只写入经过验证的模型。
22. 作为运行真实导入的学习者，希望 AnkiConnect 返回成功后仍重新读取模型，以便实际状态而不是接口返回值决定是否继续。
23. 作为遇到模型二次验证失败的学习者，希望本次导入立即停止，以便不向不一致模型写入卡片。
24. 作为遇到模型更新中途失败的学习者，希望工具不执行高风险自动回滚，以便避免第二组失败修改扩大问题。
25. 作为重试模型更新的学习者，希望下次运行根据实际 Anki 状态继续修复，以便部分更新能够收敛到完整模型。
26. 作为在模型同步后遇到 TTS 失败的学习者，希望已经验证成功的模型更新得到保留，以便下次运行无需重复恢复旧状态。
27. 作为检查导入计划的学习者，希望 dry-run 明确显示 `create`、`update`、`none` 或 `blocked`，以便判断真实导入将执行什么操作。
28. 作为检查更新内容的学习者，希望 dry-run 分别显示 Front、Back、CSS、缺失字段和额外字段状态，以便定位具体差异。
29. 作为依赖自动化的 agent，希望模型检查输出采用稳定的键值摘要，以便可靠判断是否可以继续。
30. 作为排查模板版本的维护者，希望摘要显示当前与目标的短哈希，以便无需输出完整模板也能比较状态。
31. 作为关注凭据和内容安全的学习者，希望日志不打印完整卡片 HTML、CSS、note 内容或其他敏感数据，以便日志可以安全查看。
32. 作为执行 dry-run 的 agent，希望安全的创建或更新计划返回成功状态，以便可自动进入用户确认或真实导入阶段。
33. 作为执行 dry-run 的 agent，希望不可自动迁移的旧模型返回非零状态，以便后续音频和导入步骤不会继续。
34. 作为使用默认 Skill 流程的学习者，希望内置 model spec 始终作为模板真相，以便项目模板与 Anki 保持一致。
35. 作为显式指定 model spec 的开发者，希望本次运行以指定文件作为严格标准，以便能够测试或维护另一份完整模型定义。
36. 作为显式指定 model spec 的开发者，希望输出显示规范化后的绝对路径和模型指纹，以便确认实际采用的标准。
37. 作为维护同步逻辑的开发者，希望导入器和独立模型同步命令共享一个模型合同，以便两个入口不会产生不同判断。
38. 作为手工修复模型的开发者，希望独立命令支持只读 `--check`，以便不修改 Anki 就能查看完整计划。
39. 作为维护模型一致性的开发者，希望独立命令始终执行完整同步，以便不会通过 `--templates-only` 或 `--css-only` 留下部分状态。
40. 作为使用真实导入的学习者，希望无法使用 `--no-ensure-model` 绕过模型保证，以便所有卡片都遵守同一启动合同。
41. 作为并行发起任务的学习者，希望导入器和独立同步命令共享非阻塞锁，以便两个进程不会同时修改 `TRVS-Lab`。
42. 作为重复发起任务的学习者，希望第二个进程在模型写入或音频生成前停止，以便不会形成重复修改或重复 TTS 请求。
43. 作为等待当前任务完成的学习者，希望锁在成功、失败和异常退出后释放，以便后续任务可以正常运行。
44. 作为完成真实卡片导入的学习者，希望仍在整个流程成功后触发 Anki sync，以便模型、媒体和 notes 一起同步。
45. 作为只运行独立模型同步的学习者，希望命令默认不触发云同步，以便模型检查或本地修复不会产生意外同步。
46. 作为明确需要同步模型的学习者，希望独立命令提供显式 `--sync`，以便验证成功后主动同步。
47. 作为重复导入相同 encounter 的学习者，希望即使没有 note 需要更新也执行模型预检，以便模板升级不依赖本批词条变化。
48. 作为维护测试的开发者，希望模型测试使用 Fake AnkiConnect 和假音频边界，以便不依赖真实 Anki、网络或 TTS 服务。
49. 作为维护测试的开发者，希望测试观察 CLI 返回值、输出和 AnkiConnect 调用顺序，以便重构内部模块时不需要重写行为测试。
50. 作为维护全局 Skill 的开发者，希望实施并校验后同步两个全局副本，以便运行时不会继续使用旧模型判断逻辑。

## Implementation Decisions

- 新建一个共享的模型合同模块，统一负责 model spec 加载与校验、文本规范化、内容哈希、Anki 模型检查、更新计划、执行、二次验证、诊断摘要和迁移错误。导入器与独立模型同步命令不得各自保留另一套判断规则。
- model spec 必须在任何 Anki 模型修改、音频生成或卡片写入前完整加载并验证。至少验证模型名称、字段列表、唯一的 Context Anchor 模板、Front、Back 和 CSS 内容均存在且类型正确。
- 默认正式流程使用 Skill 内置 model spec。显式 `--model-spec` 仍被支持；传入后先解析为绝对路径，并以该文件展开后的完整内容作为本次运行的唯一标准。诊断摘要显示绝对路径和目标模型短指纹。
- Front、Back 和 CSS 使用相同的文本规范化规则：把 CRLF 统一为 LF，并把文件末尾换行规范为单个 LF。除此以外不折叠空格、不格式化 HTML／JavaScript／CSS，也不做语义等价判断。
- 每个规范化组件使用完整 SHA-256 比较。分别维护 Front、Back 和 CSS 哈希，并由三个完整哈希生成组合模型指纹。日志只显示足以排查的短哈希；正确性判断使用完整哈希。
- CSS 中的版本注释仅供人工阅读，不再作为是否最新的判断依据。保留、修改或删除版本注释都会作为普通 CSS 内容参与哈希比较。
- 预检读取 note type 列表、模板、字段和样式，生成一个不修改 Anki 的模型计划。计划动作至少包括 `create`、`update`、`none` 和 `blocked`，并分别描述 Front、Back、CSS、缺失字段、额外字段和迁移问题。
- `TRVS-Lab` 不存在时，预检动作是 `create`。dry-run／`--check` 只报告；真实导入和默认独立同步自动使用完整 spec 创建模型，不再要求额外启用「不存在时创建」。
- 现有模型只有一个名为 Context Anchor 的卡片模板、没有已知遗留字段时，视为可安全更新。缺失必需字段不阻断，按照 spec 中的字段顺序补充；不要求重排已有字段。
- 可安全更新的模型按固定顺序执行：补充缺失字段、更新 Front／Back、更新 CSS、重新读取完整模型并验证。未变化的组件不发送更新请求。
- 未知额外字段不参与严格模板指纹，保留并警告。不得自动删除额外字段，也不得仅因未知额外字段阻止安全模板更新。
- 模板集合不是唯一 Context Anchor、存在旧双模板、使用错误模板名，或包含已知遗留字段时，计划动作是 `blocked`。阻断状态不得执行字段补充、模板更新、CSS 更新、音频生成、deck 创建、媒体上传、note 写入或 sync。
- 迁移阻断摘要包含具体问题和现有 `TRVS-Lab` note 数量，并给出固定人工步骤：完整备份 Anki；删除旧 `TRVS-Lab` notes；删除旧 note type；重新运行导入，由工具创建最新单卡模型。工具不自动执行其中任何删除动作。
- 创建或更新后必须重新读取 Front、Back、CSS 和字段。只有 Front／Back／CSS 完整哈希相等、全部必需字段存在、模板集合兼容且无遗留字段时，验证状态才是 `exact`。
- AnkiConnect 更新调用成功但二次验证不为 `exact` 时，返回非零状态并停止后续流程。错误摘要报告不一致组件和当前／目标短哈希，不输出完整模板正文。
- 模型更新中途失败不自动回滚。已经完成的安全字段或模板修改保留；摘要列出已完成组件和失败组件。下次运行基于实际状态重新生成计划并继续修复。
- 模型已经达到 `exact` 后，后续 Edge-TTS、deck、媒体或 note 操作失败时，不回滚模型。错误摘要区分模型同步状态与卡片导入状态。
- 真实导入顺序调整为：读取并验证输入与 model spec；取得共享锁；连接 AnkiConnect；预检模型；阻断或执行创建／更新；二次验证；准备 Edge-TTS；确保受管 deck；上传媒体；写入或更新 notes；按既有规则重置卡片；在全部成功后触发 Anki sync。
- 即使输入中的所有 encounter ID 都已存在，模型预检、必要更新和二次验证仍必须执行。模型合同不依赖本批 note 是否发生变化。
- 共享锁是本机非阻塞单实例锁，由导入器和独立模型同步命令使用同一个固定标识。锁覆盖模型预检、模型修改、二次验证以及各入口剩余的完整运行周期，并在成功、已知失败和异常退出时释放。
- 共享锁已被占用时，新进程在模型写入和音频生成前非零退出。错误信息说明已有 Anki 导入或模型同步正在运行；不排队、不自动重试，也不启动另一进程。
- dry-run 维持完全只读：不创建模型、不补字段、不更新模板或 CSS、不生成音频、不创建 deck、不上传媒体、不写 notes、不触发 sync。`create`／安全 `update`／`none` 计划返回成功；`blocked` 返回非零。
- 模型诊断使用稳定的键值摘要。预检至少报告 action、各组件状态、缺失字段数、额外字段数、迁移问题数、spec 路径和目标短指纹；执行后报告已完成与失败组件；二次验证报告 `exact` 或不一致组件。
- 独立模型同步命令保留只读 `--check`。默认调用执行完整创建或更新，并完成二次验证；模型不存在时自动创建，不再要求显式 `--create-if-missing`，也不再支持仅同步 Front／Back 或仅同步 CSS 的模式。
- 独立模型同步命令默认不调用 Anki sync。只有显式 `--sync` 且模型二次验证为 `exact` 时才触发。真实卡片导入继续仅在整个导入成功后按现有默认行为触发 sync。
- Context Anchor 真实导入拒绝 `--no-ensure-model`。参数若为兼容旧调用而暂时保留，必须在任何模型修改和音频生成前返回明确错误；不得改变模型合同。
- 导入器继续只支持 `TRVS-Lab` 单卡 Context Anchor 模型，不把共享模块扩展为任意 Anki note type 的通用迁移框架。
- 项目文档、Skill 主入口、Import 模块、独立同步命令说明、命令规则示例和全局 Skill 副本必须采用同一模型合同与命令语义。

## Testing Decisions

- 测试只断言外部可观察行为：CLI 返回状态、标准输出／错误输出、Fake AnkiConnect 收到的动作与顺序、假音频边界是否被调用、模型最终状态以及锁冲突行为。不得锁定私有辅助函数名称或共享模块内部数据结构。
- 最高测试接缝是导入 CLI 的完整 `main` 流程。使用 Fake AnkiConnect 提供模型状态并记录动作，使用临时 model spec 和假音频生成器进入一次完整导入。该接缝覆盖预检、计划、创建／更新、二次验证、TTS 顺序、卡片写入和 sync 决策。
- 第二个必要接缝是独立模型同步 CLI 的 `main` 流程。它使用同一 Fake AnkiConnect，验证 `--check`、默认完整同步、显式 `--sync`、移除局部同步模式以及与导入器相同的计划和验证结果。
- 不为文本规范化与哈希建立锁定私有函数的独立测试。通过两个 CLI 接缝提供 CRLF、LF、不同文件末尾换行、普通空格变化、HTML 变化、JavaScript 变化和 CSS 变化，观察是否产生正确计划与更新请求。
- 沿用项目现有 `unittest`、临时目录和 Fake Client 风格。现有模型同步测试、音频失败策略测试和 Context Anchor 导入路由测试是优先复用的测试基础。
- 增加模型不存在的 dry-run 验收：返回成功，报告 `action=create`，不调用任何模型修改、音频、deck、媒体、note 或 sync 动作。
- 增加模型不存在的真实导入验收：完整创建模型，重新读取验证为 `exact`，然后才调用假音频边界和后续导入动作。
- 增加严格一致验收：Front、Back、CSS 哈希相等且必需字段齐全时，报告 `action=none`，不调用模型修改 API。
- 增加换行规范化验收：CRLF／LF 和文件末尾换行差异不触发更新；其他空格差异必须触发对应组件更新。
- 增加组件差异验收：分别只改变 Front、Back、CSS，验证计划和 AnkiConnect 更新请求准确覆盖变化组件，并最终达到 `exact`。
- 增加固定更新顺序验收：缺失字段先补充，随后更新 Front／Back，再更新 CSS，最后重新读取；音频调用必须发生在验证成功之后。
- 增加二次验证失败验收：Fake AnkiConnect 在更新后继续返回旧内容时，CLI 非零退出，不调用音频、deck、媒体、note 或 sync。
- 增加旧双模板、错误模板名和遗留字段验收：全部返回 `blocked`，报告具体问题与 note 数量，不调用任何修改或音频动作。
- 增加未知额外字段验收：报告警告、保留字段、允许安全模板更新，不调用字段删除 API。
- 增加自定义 model spec 验收：输出解析后的绝对路径与目标短指纹，严格比较以自定义内容为准，正式 Skill 默认测试仍使用内置 spec。
- 增加无效 model spec 验收：在模型修改和音频生成前返回非零，不打印完整模板内容。
- 增加 dry-run 返回值验收：`create`、安全 `update` 和 `none` 返回成功；`blocked` 返回非零；所有 dry-run 分支保持只读。
- 增加参数合同验收：真实导入传入 `--no-ensure-model` 时明确失败；独立同步命令不再接受 `--templates-only`／`--css-only` 局部更新；`--check` 保持只读；模型不存在时默认计划创建。
- 增加同步语义验收：独立完整同步默认不调用 sync，显式 `--sync` 仅在验证为 `exact` 后调用；真实导入仅在卡片流程全部成功后调用。
- 增加后续失败验收：模型验证成功后假音频或 note 写入失败，模型更新保留，不执行自动回滚，也不调用最终 sync。
- 增加幂等 encounter 验收：即使没有 note 字段更新或卡片重置，仍先完成模型预检和必要更新。
- 增加共享锁验收：导入器持锁时启动独立同步，或独立同步持锁时启动导入器，第二个入口都在模型修改和音频生成前非零退出；持锁进程结束后新运行可正常取得锁。
- 增加锁释放验收：正常完成、迁移阻断、AnkiConnect 错误、模型验证失败、音频失败和未预期普通异常路径均释放锁。
- 增加日志安全验收：摘要包含动作、组件状态和短哈希，但不包含完整 Front、Back、CSS、note 内容、认证信息或音频命令中的敏感参数。
- 默认自动化测试不连接真实 Anki、不调用真实 Edge-TTS、不修改本机 note type，也不触发真实 Anki sync。

## Out of Scope

- 不自动删除、重命名或迁移旧模板、旧字段、旧 notes 或旧 note type。
- 不自动备份 Anki collection，也不在兼容模板覆盖前生成本地 Front／Back／CSS 快照。
- 不实现模型更新事务回滚。部分安全更新失败后保留实际状态，由下次运行继续修复。
- 不删除未知额外字段，也不把字段顺序或未知额外字段纳入 Front／Back／CSS 的严格内容指纹。
- 不把不同空格、HTML 结构、JavaScript 写法或 CSS 语义视为等价；只规范化 CRLF／LF 和文件末尾换行。
- 不提供 `--templates-only`、`--css-only` 或跳过模型保证的真实导入模式。
- 不把共享模型合同扩展为任意 Anki note type 的通用版本管理或迁移系统。
- 不实现跨设备、分布式或多用户 Anki 模型锁，也不阻止用户在 Anki 界面中手工编辑模型。
- 不在模型更新或后续导入失败时自动触发 Anki 云同步。
- 不改变 Context Anchor 卡片内容、学习分组、deck 路由、encounter 幂等、卡片重置、Edge-TTS 重试或音频硬门槛。
- 不修改欧路词典导出、日期范围限频保护或 coach 内容生成规则。
- 不在默认自动化测试中连接真实 Anki、调用真实 TTS 或执行真实 sync。
- 不在本规格中执行实现、修改全局 Skill 或发布到项目 Issue Tracker。

## Further Notes

- 当前实现已经具备模型不存在时创建、缺失字段补充、模板与 CSS 更新、旧双模板阻断和遗留字段检测，可以作为严格模型合同的迁移基础。
- 当前「最新模板」判断只检查关键字符串和 CSS 版本注释，无法满足严格一致要求。实施后应删除或停用这些启发式判断，避免新旧规则并存。
- 当前导入顺序先准备音频，再确保模型。实施时必须调整为模型验证优先，并以测试明确证明音频边界在 `Model verify: status=exact` 之后才会被调用。
- 当前独立同步命令默认会同步 Anki，并提供 `--templates-only`／`--css-only`；目标合同改为默认不云同步、显式 `--sync`、不允许部分同步。
- 模型锁与欧路导出锁解决不同资源的并发问题，必须使用不同固定标识。模型锁由 Anki 导入器和模型同步命令共享，欧路导出锁继续只保护欧路请求。
- 严格哈希比较不依赖人工维护的版本号。版本注释仍可保留，但任何注释变化都会作为 CSS 内容变化被同步。
- 未知额外字段被允许保留是有意的安全例外。它们会产生警告，但不削弱 Front、Back、CSS 和必需字段的启动合同。
- 本文档根据已完成的 `grilling` 设计会话保存到本地。测试接缝采用现有 CLI、Fake Client 和假音频边界，不新增面向用户的测试入口。
